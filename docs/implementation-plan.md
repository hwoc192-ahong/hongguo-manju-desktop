## 第一阶段早期结论（2026-10-14）

已实现并运行独立 Node 验证程序，完成两部作品的搜索、分享解析和分集顺序比对。第二部为《反向拿捏：和闺蜜穿七零带着婆婆一起离》，共 126 集。分享页取得 12 个推荐；推荐作品元数据已交叉核对，完整播放仍未通过。

候选网页源对两部剧均声明仅开放前三集。抽查第 78/155 集与第 64/126 集，详情页 HTTP 404、播放接口 HTTP 403；分享视频抽查均为 30.1 秒。参考短剧请求及仅更换 aid 的漫剧试探请求共八次，均为 HTTP 200 空响应。当前证据不能证明该请求方式适配独立漫剧 APP，也不能说明所有接入路线均不可行。

按照用户批准的停止条件，第二阶段暂停，没有开发正式界面或安装包。恢复条件是取得可以正常覆盖全集的内容入口，并通过完整时长、实际播放到结尾、拖动、连续跨集和推荐作品的相同验证。详细实测和替代路线见 research/REPORT.md。

## 用户指定桌面项目的后续验证

新单集接口 /novel/player/video_model/v1/ 配合新鲜签名，已取得两部漫剧的真实资源。155/126 集列表与原分享/网页列表逐集一致。最终 v3 测试对两部各抽查第 1、2、3 集、中间集及末集，3 倍速从头完整播放，每集时长与详情及资源模型比对，并有非零解码帧、音频字节。进度跳转及恢复通过；自动连播有 ended → 下一集 playing 的事件记录。推荐榜作品《菩提现》第一集使用同一路径通过；推荐榜、热播榜、新剧榜的返回选择器与请求分类核对，各取得 15 个条目。内容技术门槛已通过，详见 research/NATIVE-REPORT.md 和 research/current-result.json。

研究播放器目前先校验并暂存整集、进行媒体处理，再播放；即时起播、高清性能和人工试听尚未验收。它运行于本机 JVM/unidbg 和 FFmpeg，无手机、完整 Android 模拟器及账号依赖，但尚不是自动管理这些组件的桌面程序。

用户指定仓库不公开应用源码。研究使用的签名/密钥处理参考仓库未找到根许可证，相关第三方代码未纳入项目可分发源码与安装包。正式接入需取得明确许可，或完成独立实现；不能将技术验证通过描述为可直接复制参考源码交付。正式界面及安装包尚未开发。

## 执行顺序

1. 审查候选源码及许可，保存来源和哈希；不运行第三方安装包。
2. 用 Node 内置测试验证分享数据解析、HTTP 空响应判定、验收门槛和隐私字段处理。
3. 执行在线验证程序，记录两部剧的元数据、推荐、搜索与原生接口响应；使用隔离浏览器核对网页媒体时长和播放行为。
4. 生成机器可读结果和中文报告，只有全部内容验收通过才开始 Electron＋React＋TypeScript 桌面开发。

## 后续桌面模块（前置验收通过后）

统一内容接口：search、resolveShare、getSeries、getPlayback、getRecommendations。Electron 主进程负责联网和本地数据，预加载脚本提供有限 IPC，React 渲染进程负责推荐、搜索、详情、播放器与收藏页面。观看记录仅保存于本地应用数据目录。播放地址失效重新解析一次；接口异常和仅预览状态明确显示。
