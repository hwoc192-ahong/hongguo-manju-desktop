# 连续观看与缓存体验优化

用户已授权实施上一轮五项建议，并增加跨季自动播放、提前缓存下一季及完结推荐。本轮直接推进实现、验证和发布，不再增加设计确认轮次。

## 设计

保留现有 UI 风格和手动确认更新。拆分为独立下载器、缓存策略、播放体验三部分：下载器校验 Range/If-Range 和资源指纹，保留不含 URL/密钥的断点；缓存设置增加容量预算、总限速和作品优先级；播放器保存音量/静音/连播/画质偏好，增加画中画、定时停止、诊断导出。

边下边播先验证 MP4 索引和加密流处理。可渐进解码的源通过 FFmpeg 生成分片 MP4，主进程提供受控本地流；不支持渐进处理时回退完整准备，禁止把预览或不完整文件标记为完整缓存。完整文件仍走现有 Range 播放。取消、退出、删除和迁移均等待真实后台完成。

跨季只自动衔接标题主体一致、季数恰好 +1 的唯一候选；重复版本/缺季/无明确季数不自动猜测。观看当前季时预备确定的下一季；末集结束且连播开启时切入下一季首集。跨季不重新创建全屏容器，倍速、音量和定时计划持续。无后续季时在视频结束画面显示至多六张同题材卡片，点击才播放；播放/来源失败不当作“无下一季”。关闭到托盘不自动连播，定时到点或看完指定集数同样阻止跳集和跨季。

## 实施接口与验收

- [x] 下载：`downloadMedia({url,path,metadataPath,size,fingerprint,signal,onProgress,onChunk,throttle})`；断点持久、206 区间校验、200 安全重启、资源变化重启、超时按空闲时间、取消保留前缀。测试使用真实本地 HTTP。
- [x] 缓存策略：`CacheLimits {maxGiB,bandwidthMiB}`、`CachePriority = high|normal|low`；CacheManager 持久设置，MediaCache 执行容量/速率与公平优先调度，CacheCenter 提供入口。达到预算暂停新任务而非静默删除受保护内容。
- [x] 播放：同季/跨季连播、下一季准备、完结卡片、画中画、定时与 N 集停止、偏好记忆、真实画质上限选择；独立状态函数测试与 Electron 全屏场景验证。
- [x] 媒体：验证可渐进源的首帧早于下载结束、视频和音频到结尾、拖动边界/回退、取消/重开完整缓存；旧缓存兼容、画质切换不混用错误资源。
- [x] 诊断：分阶段耗时与错误码的有界记录，用户主动另存 JSON，只导出白名单字段，不含账号、签名、媒体 URL、密钥或用户目录。
- [x] 集成：全测试、类型检查、构建、独立审查、真实 Electron QA、安装包和更新回归、文档截图/发布与远程附件校验。

## 工程依据

HTTP Range/If-Range 依赖服务器明确返回 206 与匹配的 Content-Range；强 ETag 可用于避免把不同版本拼接。MP4 的 moov 索引位置和 FFmpeg 是否能从非可寻址输入读取，决定是否能渐进解码；FFmpeg 分片 MP4 通过 empty_moov 与 frag_duration 等标志输出。已下载官方资料到 outputs 供核对，具体可行结论由受控与线上样本共同验证。
