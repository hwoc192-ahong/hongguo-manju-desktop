# 整剧缓存验收

日期：2026-10-23，版本 0.2.10，Windows x64。

## 改动与边界

五集窗口改为当前作品全部剧集：当前集优先，后台顺序准备后续，再补前面的集数。每集完成下载和兼容转码后才计入“已缓存”。暂停播放时继续准备；离开作品详情页或关闭应用取消未完成任务，保留已完成文件。

当前整剧不受原 1 GiB 清理目标限制，重开可复用；切换其他作品后，旧缓存重新参与大小、年龄和空间清理。每次新准备前先检查并预留约 1.3 GiB 空间；不足时尝试清理其他作品，仍不足则暂停并提示。不能把整剧缓存当作永久下载归档。

整剧全部就绪后，不再因逐集下载和转码而等待。用户报告的二倍速卡顿尚未通过现场指标区分网络、转码等待和解码性能；本次处理增加准备提前量，不能宣称修复所有卡顿。若边看边缓存赶不上播放，可暂停等到“全剧已缓存”后观看。

## 自动验证

`npm test` 91 项通过，`npm run typecheck` 和生产构建通过。新增回归覆盖：

- 连续准备 12 集，超过五集不中止，只把已完成媒体计入进度。
- 从中间集开始，先向后准备，再补前面，已完成集不重复下载。
- 九集合计超过 1 GiB，离页与应用重开后全部保留。
- 空间不足暂停、已有缓存仍能播放，腾出空间后重试恢复。
- 单集失败不误报完成，重试补齐失败集。
- 全剧调度中手动跳集，所选当前集抢占后台任务。

原有关闭取消、清晰度优先、倍速记忆、收藏进度及更新器确认下载测试同时通过。

## 真实播放器验证

`node scripts/buffer-qa.mjs` 使用生产 preload、MediaCache、真实本地 HTTP、随包 FFmpeg 和生成的含音轨视频，共八集，不使用线上整剧批量下载代替测试。本机报告 `outputs/buffer-qa-1792754396057/report.json` 的 `passed` 为 `true`：

1. 打开首集并暂停，八集全部准备完成，界面显示“已缓存 8/8 集”“全剧已缓存”。
2. 内容来源切为不可用后，二倍速手动下一集、自然结束进入第三集均播放，保持同一全屏元素。
3. 跳到末集仍保留整剧；离开详情页保留八个完整文件。
4. 关闭并重新启动真实应用进程，缓存仍为 8/8，二倍速保留，未重新下载来源视频。

全屏独立回归 `node scripts/fullscreen-qa.mjs` 已通过控制栏隐藏、暂停显示、手动上下集、自然结束连播和倍速跨进程记忆检查，报告为本机 `outputs/fullscreen-qa-1792754634557/report.json`。机器报告保存在本机 `outputs/`，不上传生成媒体、内容凭据或用户数据。

本地八集验收证明缓存调度、界面和实际播放器的衔接，不等于验收全部线上作品；未在全新 Windows 电脑上运行本版，也未安装覆盖用户现用程序。
