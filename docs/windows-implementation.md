# Windows 客户端实施

用户已批准阶段二。沿用 Electron、React、TypeScript、个人使用、Windows x64、独立启动、推荐/热播/新剧榜、搜索/分享导入、收藏、续播和自动连播。

## 实施边界

不复制未明确许可的研究仓库 Java/Python 源码进正式源码。根据已观察到的请求协议、JNI 操作和资源格式实现自己的桥接、解析及媒体处理代码。第三方 JVM/unidbg/FFmpeg 和签名 SDK 二进制的来源分别记录，不以本项目 GPL 重新授权；当前只构建用户本机个人版本，不做公共分发。SDK 二进制的再分发许可仍未核实，公共发布需另行解决。

## 模块与验证顺序

1. 明确共享类型及五项内容能力，界面与 Electron 隔离。
2. 实现签名子进程（stdio 串行 JSON、自动启动/退出）、媒体暂存/校验、内容密钥处理、标准 MP4 及受限本地媒体协议。
3. 实现来源推荐/搜索/分享/详情/资源获取，错误不自动替换作品。
4. 实现推荐、搜索、详情、播放器、收藏和历史界面，保持视频比例，按集保存续播进度。
5. 实现应用数据目录中的原子持久化、失败重试一次、缓存回收及退出清理。
6. 验证接口、进度和持久化；运行真实 Electron 验证播放、切集、推荐及退出重开。
7. 构建 Windows x64 安装包、校验摘要并进行本机安装启动验证。无法在本机证明“全新无开发环境电脑”验收，报告中保留该限制。

签名及媒体密钥仅留在主进程/其子进程内；渲染层只获得作品元数据、本机媒体 URL 和明确的错误。实现开发日志时不输出 CDN URL、签名或密钥。
