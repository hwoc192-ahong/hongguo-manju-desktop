# 下载、安装与使用指南

[返回项目首页](../README.md) · [查看界面截图](../README.md#界面预览) · [发布页面](https://github.com/lhljpt-web/hongguo-manju-desktop/releases)

## 先确认下载状态

0.2.10 Windows x64 测试版已提供安装包、源码归档和 SHA-256 校验文件。

**[直接下载 Windows x64 安装包](https://github.com/lhljpt-web/hongguo-manju-desktop/releases/download/v0.2.10/Hongguo-Manju-0.2.10-Windows-x64.exe)** · [发布页面与校验文件](https://github.com/lhljpt-web/hongguo-manju-desktop/releases/tag/v0.2.10)

普通用户选择 `.exe`，下载后双击安装即可。Source code ZIP 或 Code → Download ZIP 得到的是开发源码，不能双击安装。此版本为测试版，仍有 [已知限制](releases/v0.2.10.md)。

## 系统要求

| 项目 | 要求或说明 |
| --- | --- |
| 系统 | Windows 10 / 11，x64（64 位） |
| 网络 | 获取榜单、搜索、作品详情和播放内容需要联网 |
| 磁盘 | 需留出整剧媒体缓存空间；新准备前预留约 1.3 GiB 可用空间，不足时暂停缓存 |
| 手机 | 完整个人构建运行时不需要手机或 Android 模拟器 |
| 开发环境 | 完整安装包不需要额外安装 Node.js、Python 或 Java |
| 其他平台 | 暂未提供 macOS、Linux 或 Windows ARM64 安装包 |

可在 Windows「设置 → 系统 → 关于 → 系统类型」核对设备是否为 x64。项目做过本机安装与隔离运行环境检查，尚未在全新的无开发环境 Windows 电脑上完成验证。

## 在 GitHub 哪里找安装包

1. 打开 [本仓库](https://github.com/lhljpt-web/hongguo-manju-desktop)，核对地址中的账号为 `lhljpt-web`，仓库名为 `hongguo-manju-desktop`。
2. 电脑宽屏页面通常在右侧显示 Releases；窗口较窄时位置可能变化，也可直接进入 [发布列表](https://github.com/lhljpt-web/hongguo-manju-desktop/releases)。
3. 打开 0.2.10 测试版，展开 Assets，选择 `Hongguo-Manju-0.2.10-Windows-x64.exe` 安装附件。
4. `.exe` 是 Windows 安装程序；`latest.yml` 是软件自动更新所需的元数据，普通用户不用打开；`SHA256SUMS-0.2.10.txt` 用于手动校验文件。Source code (zip) 和 Source code (tar.gz) 是 GitHub 自动提供的源码归档。

此版本标记为 Pre-release（测试版）。如果没有显示在 Latest 入口，请直接进入 [0.2.10 发布页面](https://github.com/lhljpt-web/hongguo-manju-desktop/releases/tag/v0.2.10)。

## 安装程序

1. 保存 `Hongguo-Manju-0.2.10-Windows-x64.exe`。文件约 174 MiB，下载或复制时需等待文件完整写入。
2. 如果同时取得 `SHA256SUMS-0.2.10.txt`，可以按下一节核对文件摘要。
3. 双击 `.exe`，按安装向导选择安装目录，再执行安装。
4. 完成后从桌面快捷方式或开始菜单启动「红果漫剧桌面版」。
5. 进入首页后等待榜单载入，点击作品，再进入播放或选择指定集数。

此个人构建尚未配置 Windows 发布者代码签名。若系统提示未知发布者，先核对文件来源和摘要；摘要只能证明文件一致，不能代替发布者身份认证。不需要关闭系统防护。

### 可选：核对文件摘要

在安装文件所在文件夹打开 PowerShell，执行：

```powershell
Get-FileHash -LiteralPath '.\Hongguo-Manju-0.2.10-Windows-x64.exe' -Algorithm SHA256
```

安装包摘要见对应发布页面的 `SHA256SUMS-0.2.10.txt`，对照同版本文件逐字符核对结果；十六进制字母大小写不影响比较。同版本如果重新构建，应以对应附件同时提供的校验文件为准。

## 首次打开后怎么用

### 浏览与搜索

搜索关键词最多 30 字；结果来自官方搜索接口，可能包含近似匹配作品。结果下方出现「发现更多」时可继续加载下一页，上游暂不可用时可点击重试。

顶部「推荐」「热播」「新剧」切换不同榜单。点击作品卡片查看详情和剧集列表；搜索框可以输入完整剧名。对相近标题、不同季数或同名版本，请先核对作品名称，再播放。

![首页推荐与搜索入口](screenshots/home.webp)

### 导入分享链接

1. 在手机端打开作品的分享功能，复制链接或分享文字。
2. 在桌面端点击右上角「导入链接」。
3. 将内容粘贴到输入框，点击「导入并收藏」。
4. 解析成功后核对作品标题、集数和顺序，再开始观看。导入成功的作品会加入本地收藏。

![分享导入窗口](screenshots/share-import.webp)

导入只识别受支持的来源链接。链接失效或解析失败会显示错误，不会自动替换为其他作品。

### 播放、选集与续播

右侧点击集数切换剧集；播放器下方可暂停、拖动进度、调整音量和倍速，或进入全屏。倍速会记住上次设置，手动换集、自动连播、切换作品和重开软件都继续使用。全屏时控制栏浮在画面上，播放中闲置约 2.5 秒隐藏，移动鼠标可唤出；暂停或操作控件时保持显示。开启自动连播后，当前集结束时进入下一集；自动连播与手动上下集均保持全屏。按 Esc 或点击全屏按钮退出。首版会先准备完整单集再起播，首次加载耗时取决于网络与文件大小。

![播放与选集界面](screenshots/player.webp)

收藏和播放进度保存在当前电脑。下次打开后，可以从首页继续观看卡片或「历史」返回作品；收藏列表与观看历史不是手机账号同步数据。

## 升级、卸载与记录

0.2.4 起采用手动确认下载：启动后自动检查，发现新版只提示。点击「立即更新」才下载，选择「暂不更新」不会下载。点击顶部「更新」查看进度，下载并校验完成后点「重启安装」，应用先保存观看记录，再升级并重新打开。收起面板可以继续观看；普通退出不安装更新。更新失败可在面板中重试，GitHub 无法连接时也可手动下载本仓库新安装包覆盖安装。

**0.2.2 及更早版本没有更新器，需先手动下载安装一次 0.2.10。** 0.2.3 仍采用旧的自动下载行为；如需避免它后台下载，请关闭旧版后手动覆盖安装本版。 此后无需每次访问网页下载；更新包含本仓库测试版。升级时保留相同的应用数据目录和安装路径，收藏、播放进度及播放标识会沿用。详见 [应用内更新说明](auto-update.md)。

卸载可在 Windows「设置 → 应用 → 已安装的应用」（不同系统名称可能略有差异）中找到「红果漫剧桌面版」并选择卸载。默认保留个人记录。

数据目录：

```text
%APPDATA%\红果漫剧桌面版\
```

`library.json` 保存收藏与观看位置，`player-profile.json` 保存本次安装的固定播放标识，`media-cache` 保存媒体缓存。升级时保留播放标识，不通过删除或轮换标识处理内容服务错误。需要备份时，先关闭程序，再复制 `library.json`。清理空间时不要误删观看记录；缓存损坏可在程序关闭后仅清理 `media-cache`，下次播放会重新准备媒体。

## 从源码运行（适合开发者）

### 1. 下载源码

在仓库首页点击 Code → Download ZIP，解压到本地文件夹。安装 Node.js 22 或更新版本，并在解压后的项目根目录打开 PowerShell；这里应能看到 `package.json`。

也可以使用 Git：

```powershell
git clone https://github.com/lhljpt-web/hongguo-manju-desktop.git
cd hongguo-manju-desktop
```

### 2. 安装依赖并检查

```powershell
npm ci
npm test
npm run typecheck
npm run build
```

上述步骤用于源码检查与编译；通过不表示已经具备连接内容服务的全部运行组件。

### 3. 准备运行组件

当前仓库没有自动补齐全部组件的下载器。需要先准备 [运行组件说明](runtime-components.md) 中的 Java、桥接类、依赖 JAR、SDK 和 FFmpeg，再形成下列目录：

```text
runtime-bundle/
├── java/bin/java.exe
├── classes/app/hongguo/runtime/SignerBridge.class
├── dependencies.jar
├── sdk/
│   ├── libmetasec_ml.so
│   ├── libc++_shared.so
│   └── ms_16777218.bin
├── ffmpeg.exe
└── notices/
```

已有完整本机个人构建时，可从安装目录的 `resources/runtime-bundle` 复制整个目录到源码根目录。仅安装系统 Java 或 FFmpeg 不能替代这套固定组件。`npm run runtime` 依赖原研究环境的输入文件，不能在全新电脑上直接自动下载完成配置。

### 4. 启动或打包

```powershell
npm start
```

准备好完整组件后，如需生成供本机使用的安装包：

```powershell
npm run package:win
```

输出在 `release/`。个人构建成功不等于所有第三方组件的公开分发许可已经确认，许可状态请查阅运行组件说明。

## 常见问题

| 现象 | 说明与处理 |
| --- | --- |
| 右侧没有找到安装包 | 直接进入 [0.2.10 发布页面](https://github.com/lhljpt-web/hongguo-manju-desktop/releases/tag/v0.2.10)，展开 Assets 并选择 `.exe`；不要下载 Source code ZIP 作为安装包。 |
| 下载了 ZIP，找不到可执行程序 | 这是源码归档。开发者可按上面的源码运行步骤操作，仍需准备完整运行组件。 |
| 启动提示应用数据或运行组件无法读取 | 检查安装是否完整、应用数据目录是否可写；源码运行时还需检查 `runtime-bundle` 是否齐全。 |
| 首页为空、搜索失败 | 检查网络并重试。同一网络能打开网页，不代表所有内容接口都可用；也可能是上游接口变化。 |
| 分享链接导入失败 | 重新复制作品的原始分享内容，检查链接是否完整；仍失败时记录提示原文和作品标题。 |
| 点击播放后需要等待 | 当前版本先准备完整单集再起播。持续失败时重试当前集一次，再换另一部作品对照。 |
| 黑屏或中途报错 | 查看错误提示，手动重试当前集；若只在特定剧集出现，反馈作品、集数与操作步骤。 |
| 手机收藏和观看历史没有出现 | 首版只保存在本机，不接入手机账号，也不支持跨设备同步。 |
| 推荐内容与手机不同 | 榜单来自当前接入的内容来源，不是手机账号的个性化推荐。 |
| 这是独立漫剧 APP 的完整电脑版吗 | 尚不能这样称呼。正式客户端仍使用现有短剧/TV 接入，独立漫剧 APP 的原生搜索与首页未完成验证，详见 [接入报告](independent-app-validation.md)。 |

如果仍有问题，请到 [本仓库 Issues](https://github.com/lhljpt-web/hongguo-manju-desktop/issues) 提交 Windows 版本、应用版本、作品与集数、复现步骤、预期结果和错误提示。截图请遮住无关个人信息，不要提交账号凭据、签名或完整播放地址。

## 整剧提前缓存

打开作品后先准备当前集，随后在后台逐集准备后续全部剧集，再补齐较早的集数。当前作品的全部剧集完成下载和兼容转码后，界面显示“已缓存 N/N 集”和“全剧已缓存”；失败的集数不会计入完成，可点“重试缓存”补齐。后台一次只准备一集，跳到未缓存集时优先准备所选集，然后继续整剧队列。

即使暂停或关闭自动连播，停留在详情页内也会继续缓存并使用网络流量。想先缓存好再看，可暂停并等待“全剧已缓存”。离开作品详情页或关闭软件会取消未完成任务，已完成的缓存保留，重开作品可以复用。单次作品列表最多 5000 集，单集上限 150 MiB。

缓存目录为 `media-cache`。当前整剧受保护，允许超过原来约 1 GiB 的清理目标；换到另一部作品后，旧作品缓存可按大小、年龄和可用空间自动清理，不能作为永久下载归档。每次准备新集前预留约 1.3 GiB 可用空间，优先清理其他作品缓存，仍不足时暂停并提示；现有缓存仍可播放，释放空间后可点击“重试缓存”恢复。临时下载与转码文件另需空间。

二倍速可能比后台准备更快，全剧完成前仍可能等待；全部就绪后可避免逐集下载和转码等待，但缓存不能保证消除解码、渲染或硬件性能造成的卡顿。它只用于应用内播放，不提供下载导出。验证方法见 [整剧缓存验收](full-series-cache-validation.md)。

## 清晰度

0.2.9 起按 1080p → 720p → 540p → 480p → 360p 的顺序选择来源提供且可解码的轨道，播放器显示实际选择的分辨率。只提供低清轨道的集数无法凭空变高清，也不把低清放大后标为高清。高清文件通常更大，首次准备和后台缓冲可能更久。

升级自 0.2.8 或更早版本时，旧画质策略产生的媒体缓存需要重新准备；0.2.9 的新画质缓存可直接复用。升级不影响收藏、观看进度和播放标识，新的高清缓存用于整剧提前缓存。
