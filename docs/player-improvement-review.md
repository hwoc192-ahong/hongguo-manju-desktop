# 播放与缓存体验审视（0.4.0 基线，0.5.0 跟进）

2026-10-24 根据代码和实际验收，参考成熟播放器的官方功能说明。下列问题表保留 0.4.0 时的基线；0.5.0 已落实断点续传、缓存预算/总限速/作品优先级、条件渐进播放、画中画/睡眠定时、更多偏好与实际画质选择、脱敏诊断，以及跨季衔接和完结推荐，见 [连续观看验收](continuous-playback-validation.md)。

## 仍可继续优化

1. **逐集已看状态与手动标记**：目前仍按末集达到 95% 推断整部已看完。可加入逐集记录及手动纠正，再做可选的到期清理，默认不自动删除。
2. **下一季缓存开关与单部配额**：当前确认的下一季会自动登记；可进一步让用户选择提前准备的范围、时间及每部预算。
3. **自定义片头片尾**：先提供单部手动秒数，不使用缺乏依据的统一跳过时长。
4. **硬件处理评估**：先检测机器能力并测量首帧、处理速度与兼容性，再决定硬件编码/解码和回退策略。
5. **快捷键帮助、字幕和音画同步**：当前已有常用快捷键，可增加可见说明；字幕需可用来源或用户本地文件。

## 优先解决等待和空间管理

| 优先级 | 建议 | 当前问题与实现条件 |
| --- | --- | --- |
| 高 | 断点续传、分阶段超时和自动退避重试 | 当前失败会清理未完成文件，重启需重新下载；整段下载存在 45 秒超时。应先核对源站 Range、资源版本与有效期，保存校验后的临时进度，不能盲目拼接不同资源。 |
| 高 | 缓存预算、带宽上限、作品优先级 | 目前有并行数、播放优先和低空间保护，但多部受保护作品仍会持续占空间。建议允许设置总预算、单部优先级和限速，保障观看及其他网络使用。 |
| 高 | 缩短首播：验证边下边播 | 现在必须完整下载并准备单集，增加并发无法消除首集等待。应单独验证容器索引、加密处理和随机定位，支持时走渐进播放，不支持时明确回退完整准备。 |
| 高 | 更准确的已看状态、可选自动清理 | 本版按末集达到 95% 推断看完，尚无逐集观看审计。建议增加手动标记、逐集状态和“看完保留几天”，自动删除默认关闭，显示释放范围并提供足够的撤销条件。 |
| 高 | 一键导出脱敏诊断 | 记录解析、下载、等待处理、转码、保存各阶段耗时和错误，导出时去除签名、内容密钥及带凭据地址；有助于区分网络慢与 CPU 慢。 |

Netflix 的 [Download Next Episode](https://help.netflix.com/en/node/101262) 采用看完删除、准备下一集的方式，并提供开关；其适用设备和联网规则与本应用不同。这里借鉴的是可控的空间管理，不代表可以照搬其内容服务。

Plex 的 [Credits Detection](https://support.plex.tv/articles/credits-detection/) 将观看完成阈值、片尾标记和跳过片尾结合使用。本项目目前没有可靠的片头/片尾标记；不能把短视频尾部固定数秒全部跳过，也不能把末集进度推断说成逐集核验。

## 随后增加的日常功能

1. **画中画与睡眠定时**：小窗播放、看完本集停止、再播 N 集后停止，适合边工作边看及睡前观看。
2. **更多偏好记忆**：音量、静音、自动连播按本机保存；倍速目前已保存，但音量和连播仍会随播放器/详情页重新初始化。
3. **清晰度选择与资源说明**：保留最高画质默认策略，同时允许手动选择来源实际提供的档位；显示大小、分辨率和是否需要转码，避免把低清放大冒充高清。
4. **跳过片头片尾与跨季续看**：先支持用户为单部作品设定时间，获得可信标记后再自动化。跨季播放应明确确认匹配作品，不能仅按近似标题强行切换。
5. **解码与处理性能诊断**：检测硬件能力、比较原轨道复用和软/硬转码，失败回退。VLC 的 [功能说明](https://www.videolan.org/vlc/features.html) 可作为能力参考，但 Electron、打包 FFmpeg、驱动与源编码组合需单独测试，不能简单开启一个开关就承诺可用。

现有快捷键已包含空格/K 暂停、左右方向键跳转、F 全屏、M 静音；下一步可以补充可见的快捷键帮助和自定义键位。外部字幕与音画同步可作为较低优先级功能，前提是存在可用字幕来源或用户提供本地文件。

## 本版边界

0.4.0 已实现同名其他季优先推荐、相似题材、2/4/6 路缓存、真实近期下载速度、单部与已看完缓存清理。推荐依据标题、分类和关键词，不是手机账号画像，也不是经过内容理解验证的剧情推荐。更高并发只能改善存在并行余量的任务；不能保证消除网络、转码、解码或渲染造成的所有卡顿。
