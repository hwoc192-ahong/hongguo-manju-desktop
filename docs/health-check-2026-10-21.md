# 2026-10-21 日常检查：间歇性播放失败

检查对象：本机已安装的 Windows x64 0.2.6。结论：部分复测可以播放，但本轮存在多次播放资源空响应，不能宣布全面恢复，也没有通过完整回归的修复版本。

## 本次证据

- 78 项自动测试、类型检查、生产构建、发布元数据和安装包校验通过。
- 首页和推荐、热播、新剧榜可加载；作品详情及搜索可返回。
- 第一轮安装版界面打开《糯糯下山，师兄们都慌了》首集失败，提示媒体准备失败。磁盘空闲充足，不能据界面提示认定磁盘不足。首次底层异常未被原客户端保留，具体原因未确定。
- 新隔离目录复测另一推荐作品《东北后妈，整顿全家》首集失败，界面明确为“内容来源返回空结果”。
- 原有默认用户目录和首次隔离目录的资源请求对照均出现 `API_EMPTY`。没有修改或轮换已有播放器标识。
- 诊断使用本机已配置代理后，一部推荐作品资源获取及媒体处理成功；随后直连另一推荐作品也成功。此结果不足以证明必须使用代理，也不能证明故障已消除。
- 代理环境对照的实际安装版流程：推荐作品、搜索、分享导入、拖动/音量/倍速/全屏通过；第 1、2、3 集完整播放到自然结束并自动换集，画面和音频解码均有记录。但随后第 78 集空响应，整套流程保持失败。
- 最后一次默认网络安装环境检查通过：版本确认为 0.2.6，3 项 SDK 摘要一致，仅系统 PATH 下推荐/热播/新剧榜均 15 项；首集和下一集有画面、音频解码，收藏和保存 12 秒后重开恢复通过，默认目录启动正常。这是部分恢复证据，不覆盖此前失败的全部路径。

## 原因判断与修复边界

可以定位的故障发生在上游播放资源模型获取阶段：收到 HTTP 成功但空的响应体，尚未进入该次请求的媒体解码。它与首页、详情可用并不矛盾。当前没有证据证明账号/IP/设备被封禁，也没有证据证明必须更换接口、标识或安装包。

参考项目 [1.0.16 发布说明](https://github.com/waligoraamodio288-rgb/hongguo-desktop-releases/releases/tag/v1.0.16) 同样报告播放接口偶发空数据，采用最多两次延迟重试，并注明持续不可用时仍会失败。这只是相关外部证据，不能代替本项目修复验证。本项目现有媒体准备已最多尝试两次，本轮仍有失败；没有证据表明只增加次数或延迟就能稳定恢复，因此未擅自更换请求配置、强制代理或宣称修复。

本轮未修改应用运行代码、未发布新安装包。故障记录同步至 GitHub，保留 0.2.6 发布文件。待有可复现且通过默认网络、后续集数及安装版回归的方案后再发布修复。临时观看可使用官方应用。
