# 多作品后台缓存验收

日期：2026-10-24，版本 0.3.0，Windows x64。

## 实现与边界

缓存中心可通过分享内容、收藏和播放详情添加作品，持久化作品及分集信息。最多登记 100 部作品，每部最多 5000 集，不保存临时媒体地址、签名或内容密钥。全局最多两个准备任务，已登记作品与当前临时提前缓存轮转执行；用户播放优先，可接管已有任务或抢占后台通道。

逐作品展示完整可播放集数、百分比、占用、下载字节/处理进度、暂停和失败状态，提供继续、重试、移除。暂停只停止后台准备，主动播放仍可取得当前集。失败只有限重试，切换页面不能清除后台失败状态并触发无限重试。空间不足暂停后台准备，预留约 1.6 GiB，现有缓存仍可播放。

默认关窗隐藏到托盘并暂停视频，缓存继续；在视频资源尚未准备好时关窗，迟到的结果也不能自行播放或连播。点击托盘打开，菜单退出才停止，重开恢复未暂停任务。不提供 Windows 服务或开机自启。应用更新仍需用户点击才下载、确认重启才安装。

默认缓存目录沿用旧版，新目录只能由系统选择器选择，在其中使用专用 `HongguoManjuCache`。迁移暂停并等待媒体任务、检查空间、复制及逐文件 SHA-256 校验、原子提交目录设置，再切换；失败移除本次复制的目标文件并保留源。旧源在成功后也保留，用户确认新目录正常后可自行清理。已登记作品（含暂停）保护缓存免于普通清理；移除任务不立即删除媒体，但之后可清理。

## 自动验证

`npm test` 共 104 项（23 + 81）通过，类型检查、生产构建通过。新增测试覆盖多作品并发、后台卡住时另一部继续、暂停恢复、两条忙通道下当前播放抢占、原任务接管不重复、离页失败状态保留、轮转、队列写入失败不改变内存和调度、配置重启、损坏设置备份、迁移校验及提交失败回滚、H.264 封装失败回退。当前集准备中加入后台后离页，运行中的任务继续；尚未启动的排队播放任务安全取消登记，让后台重新选取，不能挂起或重复下载。

原实现上先验证新增失败案例，再修复；独立代码审查发现并修复“准备中关窗后迟到资源自动播放”，真实 Electron 补充该回归。

## 真实 Electron 验证

`node scripts/cache-center-qa.mjs` 使用生产主进程、preload、React 界面、媒体缓存和随包 FFmpeg。仅在测试构建时替换内容提供器为本地 HTTP 服务，生成三部共 24 集 H.264/AAC 测试视频，不向真实来源批量下载。

- 经界面添加三部作品，显示独立进度；暂停其中一部，其他继续，最多两条媒体通道。
- 准备当前集过程中关窗，结果到达后保持暂停；普通关窗隐藏后，缓存完成数继续增长，重新显示成功。
- 恢复、失败重试后 24 集完整缓存。
- 通过生产目录选择 IPC 将 24 个媒体迁移到专用新目录，校验后切换，原文件保留。
- 停用本地视频源后，新目录缓存仍解码出画面和声音；二倍速及全屏下一集正常，没有新媒体请求。
- 实际 `app.quit()` 通过关窗和保存流程退出；重启恢复队列和目录，24 集直接复用，无新媒体下载。移除一部保留另两部及文件。

`node scripts/buffer-qa.mjs` 八集整剧进度、离页、重开复用、二倍速手动及自然连播回归通过。`node scripts/fullscreen-qa.mjs` 验证沉浸式控制栏与倍速等播放行为。截图来自本地验收作品，非线上内容。

## 速度实测

`node scripts/cache-speed-qa.mjs` 使用同一个本地生成的 20 秒、1920×1080、24fps H.264/AAC 视频，运行随包 FFmpeg 的两条真实准备路径，并将两份结果的音视频完整解码到结尾：

| 路径 | 处理时间 | 输出字节 |
| --- | ---: | ---: |
| 原兼容重新编码（CRF 20） | 3211 ms | 15,548,870 |
| 复用视频轨道封装 | 259 ms | 32,660,029 |

这只说明兼容 H.264 样本可减少重复编码耗时，同时可能占用更多空间。HEVC 仍需编码；网络、片源、硬件和并发负载会改变时间，不承诺每集同等提速。完整封装失败或文件过大时回退兼容编码，不重新下载同一份输入。

本次为本机和生成媒体验收，不代表所有线上作品可用，也未在全新的无开发环境 Windows 机器上完成安装验证。
