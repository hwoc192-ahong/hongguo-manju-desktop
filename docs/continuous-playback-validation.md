## 自动化与实际播放

169 项自动测试通过（23 项 JavaScript、146 项 TypeScript/播放器测试），类型检查与构建通过。使用本地 HTTP、真实文件与可控取消验证 Range/If-Range、资源变化、重试、空闲超时、取消和恢复。缓存覆盖额度暂停/恢复、实际输出超额拒绝、并发额度预留、优先级公平、画质隔离、断点重开/迁移和安全退出。

`scripts/progressive-playback-qa.mjs` 使用生产主进程、preload、协议处理和 FFmpeg，仅替换内容来源。慢速传输 20 秒 H.264/AAC 视频，747 ms 返回渐进资源，约 1244 ms 实际解出画面和音频，均早于下载完成；完整播放到结尾、完成后中间拖动、尾部索引回退完整准备、重开零媒体请求复用均通过。时间仅代表该受控样本。

线上加密 HEVC 样本单集约 60.034 秒、1080p、4.48 MB，索引在文件前部，源站返回强 ETag 与区间响应。慢速输入 FFmpeg 约 10.2 秒输出首批分片，约 38.3 秒输入完成。该实验说明该样本具备渐进处理条件，不代表所有源均支持，也不是公网速度承诺。

同一样本进一步通过生产 Electron 主进程、preload、本地协议与浏览器视频解码：约 1167 ms 返回渐进资源、1727 ms 解出首帧和音频；以 2 倍速播放到实际 60.067 秒结束，解出 1801 帧和音频数据，完成后从中间继续播放通过。线上素材只保留本地验证缓存，不提交到仓库。

`scripts/continuous-playback-qa.mjs` 使用真实 Electron 与生产 IPC，替换三部本地测试作品。覆盖：下一季自动登记、末集真实 ended 后进入下一季首集而非旧历史位置、同一全屏容器和 2 倍速/音量保持、画中画、全屏完结卡片点击、关闭连播、睡眠停止及延迟推荐、推荐失败重试、画质选择、缓存策略、诊断白名单与重开偏好。

`scripts/cache-center-qa.mjs` 保留三部共 24 集的后台、托盘、失败重试、校验迁移、离线解码、全屏倍速和删除后重开验收。新版本使用作品 ID 定位任务，兼容下一季提前加入队列。

## 行为边界

- 下一季来自已获取的推荐候选，只在标题主体一致、季数恰好加一、候选唯一时衔接；没有明确季数、缺季、不同版本重名时不猜测。未找到不等于平台绝对没有后续季。
- 没有后续季的结束推荐最多六部，按分类/关键词；点击才进入作品首集，不自动切到无关作品。来源错误明确显示重试。
- 自动连播关闭、睡眠到点/集数用尽、关闭到托盘时不继续播放；已登记缓存仍可运行。睡眠计划只在当前运行有效。
- 断点必须同时满足资源指纹一致、强 ETag 相同、206 与 Content-Range 正确。Last-Modified、已满长度但未确认 EOF 的断点不足以证明完整，不直接采信。
- 渐进播放要求可从管道读取的前部 MP4 索引与兼容解码。流式阶段只允许已缓冲范围内定位，完成后才提供完整 Range。准备失败时不会将半成品标记为完整缓存。
- 渐进分片的浏览器临时时长不能覆盖来源总时长或历史位置。等待上次位置时可选择“从头播放”；缓存完成后可以重载同址完整资源恢复位置，避免浏览器暂停预载造成一直等待。
- 画质默认最高；手动选上限时优先不高于上限的最高源，无更低源则回退最低可用源。显示实际来源档位。质量策略不同的缓存不混用。
- 缓存预算控制保留媒体与断点，转码临时输出另需空间；操作系统和 HTTP 缓冲可能带来瞬时速率波动，总限速不是每秒精确流量承诺。高优先级取得更多轮转机会，低优先级仍有机会。
- 降低额度不会自动删除已有受保护文件；画质替换时若系统占用旧文件使删除失败，可能保留旧文件到下次启动清理，磁盘瞬时占用可能高于界面计数。
- 导出诊断只包含当前运行最近 200 条白名单事件、系统架构与应用版本，不导出任意错误文本、账号、签名、密钥、媒体 URL 或用户路径。

- [FFmpeg Formats](https://ffmpeg.org/ffmpeg-formats.html)：分片 MP4、empty_moov、default_base_moof 和 frag_duration。是否能提前播放仍由真实媒体实验验证。
