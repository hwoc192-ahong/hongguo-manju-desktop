# 连播画面衔接验收 · 0.5.2

2026-10-24 在 Windows 本机使用实际 Electron 播放器验证；没有改动用户的正式安装或个人数据目录。媒体素材为本地生成的 H.264/AAC 视频，不作为线上作品可用性证明。

## 问题与原因

切换剧集会替换以剧集 ID 为 key 的 Player。旧 video 被销毁，新 video 要等播放地址、媒体元数据和解码首帧；这段时间原实现会显示深色背景或加载层。即使下一集已缓存，磁盘缓存也不能消除播放器重建时的画面空档。

`scripts/frame-handoff-qa.mjs` 先在修复前运行：给实际播放 IPC 增加 650 ms 的受控准备延迟，自动触发 ended 后换集。旧实现记录到 45 个没有可显示视频的动画帧，切换截图中心像素 BGRA 为 `[15,18,20,255]`，复现深色背景，断言失败。

## 修复

在稳定的 PlayerSurface 中保留单张 Canvas 画面。旧 video 移除时捕获最后已显示画面，将同一个 Canvas 移入下一段的画面区域；新 video 的 `requestVideoFrameCallback` 回调确认首帧呈现后才撤去。采用视频原始尺寸及 `object-fit: contain`，不拉伸画面，也不堆积多集画面。

使用者跳集后，已取消或旧代的视频回调不能撤去当前过渡层。加载提示延后 600 ms 显示，短暂衔接不闪出大块底色；错误提示和重试操作始终保留。首次打开作品没有旧画面时仍使用正常加载界面。

保留每集独立的 Player 生命周期，避免进度、重试、睡眠状态和媒体恢复逻辑串集。此修改不更改下载队列、缓存格式、更新器或退出流程。

技术依据：[MDN：requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback) 描述该回调与视频帧送交合成器的关系；取得 URL、loadedmetadata 或 canplay 均不能单独作为画面切换依据。

## 实际验证

- `npm test`：25 项 JavaScript 与 148 项 TypeScript 测试全部通过；`npm run typecheck`、`npm run build` 通过。
- `node scripts/frame-handoff-qa.mjs`：先等两季全部缓存完成，再注入 650 ms 的播放地址准备延迟。自动下一集、自动下一季、手动下一集、窗口模式四组采样均为 0 个切换空画面。延迟期间实际截图的 BGRA 为 `[209,104,43,255]`，保留测试视频的蓝色画面；新首帧出现后遮罩撤去。全屏容器及二倍速保持。
- 同一验收还覆盖快速跳集、播放失败与重试；人为延迟已排队的首帧回调并在跳集后继续投递，确认旧回调不能提前清除新一集的过渡画面。
- `node scripts/continuous-playback-qa.mjs`：实际跨季、画中画、全屏完结推荐、睡眠停止、延迟推荐、画质、音量、静音、二倍速、退出后偏好保存通过。
- `node scripts/progressive-resume-qa.mjs`：初始分片短于保存位置时不覆盖历史；缓冲后从第 15 秒实际恢复播放，“从头播放”仍可用。上述三套桌面验收均无页面错误。

运行输出和截图保存在本地 `outputs/` 独立目录，未提交测试媒体和个人 profile。

Windows x64 安装包已生成（181,830,055 字节），内置运行组件和 SDK 摘要检查通过。ASAR 内主进程、preload、HTML、JavaScript 和 CSS 五个构建文件与本轮验收的 dist 逐字节一致，应用版本为 0.5.2；`latest.yml` 的 SHA-512 及 GitHub 更新目标校验通过。实际打包客户端的隔离更新测试通过：启动只提示，拒绝不下载，重开仍只提示，明确点击后单次下载并等待安装确认。测试更新文件未执行，正式更新源未改动。本轮未在全新 Windows 上重做安装验收。

## 边界

本次消除播放器切换期间的空画面，不等于将不同媒体文件无间隙拼接。网络或来源缓慢仍可能让上一画面短暂停留，并显示缓冲提示；无法捕获的媒体画面回退到正常加载界面。视频内容自身的黑色开头、片尾和场景不属于播放器闪黑。尚未在用户报告问题的另一台电脑上实测。
