## 当前结论

用户报告 v0.2.1 在《别惹她她会改剧情》第一集显示“内容来源返回空结果，请稍后重试”。本机使用当前源码的实际签名组件和内容模块复现。故障位于取得播放资源阶段，尚未进入媒体下载、处理或播放器解码。

初始复查时播放资源接入不可用。后续受控实验已找到可复现的请求差异，并在源码中修复；完整播放及安装包回归结果见本文后续记录。2026-10-14 的通过记录是历史验证，不代替本次回归。

## 已定位的两处客户端兼容问题

参考 [渠道有数 TV 0.5.8 的发布说明](https://github.com/waligoraamodio288-rgb/hongguo-desktop-releases/releases/tag/tv-v0.5.8) 中的播放器配置修复，下载原版 APK 核对 SHA-256 后仅做静态研究，没有运行安装包或复制私有应用源码。

对同一个作品、同一集、同一请求体进行以下对照：

| 播放请求 | 实测结果 |
| --- | --- |
| 原请求，无设备/安装标识，使用原跨 APP 签名 | HTTP 200，0 字节 |
| 原请求，无设备/安装标识，不带签名 | HTTP 200，0 字节 |
| 原请求补上固定 `device_id` 和 `iid`，使用原签名 | HTTP 200，0 字节 |
| 原请求补上同一组标识，不带原签名 | `code=0`，约 18 KiB 资源模型，第 1 集时长 153.206 秒 |

因此可复现的问题是**旧播放配置缺少当前需要的播放器标识，且旧跨 APP 签名与当前播放路径不兼容**。不据此推断用户被封禁、所有接口不再需要签名，或平台在某个日期修改了某条内部规则。

最小修复保留当前 `aid=8704`、域名、请求体和资源模型，只为播放接口补上每次安装固定的随机标识，并停止添加原签名。标识保存在应用数据目录的 `player-profile.json`；不使用账号、Cookie 或他人的设备信息，不在失败后轮换。文件损坏或不可写会明确报错。榜单、详情等请求保留原有流程。

恢复资源后，真实媒体回归发现第二处问题：《别惹她她会改剧情》第 2、4、115 集的低分辨率轨道使用 `bytevc2`，内置 FFmpeg 报告没有相应解码器。同集 1080p 轨道为可解码的 `bytevc1`。修复为先过滤支持的编码，再应用原有画质优先级；不支持的编码不再进入反复下载与处理。没有任何兼容轨道时显示明确提示，不替换作品。

回归测试先在原代码上失败，再在修复后通过，覆盖标识重启保留、并发复用、禁止覆盖/轮换、坏文件和不可写路径、其他接口仍签名，以及可解码轨道选择。
