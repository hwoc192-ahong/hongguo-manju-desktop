更新服务 6 项回归测试通过，其中确认检查、重复检查均不调用下载；明确调用下载后只下载一次，安装仍须单独确认。

`node scripts/manual-update-qa.mjs` 在隔离的 0.2.4 打包应用中通过。使用本机 HTTP 更新源与无害的下载测试文件（未执行安装），完整记录服务端请求：

- 启动约 10 秒自动检查并弹出「立即更新 / 暂不更新」，没有请求安装包。
- 点击暂不更新、切换收藏页、重新展开更新面板，没有请求安装包。

两次启动仅产生两次版本元数据请求；安装包请求仅发生于明确点击之后，renderer 无异常。该验证针对下载确认边界，不宣称完成下面所述跨版本安装重启验收。

## 0.2.3 历史记录

日期：2026-10-18 · 版本：0.2.3 · Windows x64

已完成的自动化验证：

- `tests/updater.test.ts`：6 项通过。覆盖并发检查只发一次请求、自动下载、进度事件、当前版本、失败重试、开发模式禁用、安装器启动异常和下载状态竞争。
- `npm run release:verify`：通过。`latest.yml` 与 `package.json` 版本一致，安装包文件名、SHA-512、GitHub owner/repo 和 `app-update.yml` 一致，未包含 token。
- 使用本机 HTTP 测试源：服务不可用显示错误；篡改安装包后校验不通过；原始安装包进入“已下载并校验”状态。测试只使用 `outputs/` 隔离目录。
- 1040×720 窗口 UI 检查通过，更新面板不造成横向溢出。

覆盖安装回归需要由 Windows NSIS 安装器启动并退出旧进程。当前测试环境已有多个同路径 Electron QA 进程，自动重启阶段被旧进程锁定，未把它记录为通过；不能据此声称完成跨版本安装重启验收。安装器自身仍按普通 NSIS 构建流程生成，用户首次升级应保留收藏和进度。

发布前必须在干净的 Windows 用户环境完成一次 0.2.2（带更新器的旧构建）→0.2.3 覆盖安装，观察旧进程退出、新进程启动，并核对 `%APPDATA%\红果漫剧桌面版\library.json` 与 `player-profile.json` 保留。0.2.2 正式发布包没有更新器，不能用它验证应用内更新；它只能通过手动安装升级到 0.2.3。
