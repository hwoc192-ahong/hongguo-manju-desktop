# 2026-10-22 播放兼容修复：0.2.7

## 故障与对照

原安装版 0.2.6 再次复现“内容来源返回空结果”：推荐作品《十元盒饭，卷懵吃了不烧心》首集失败；单独安装环境检查中榜单正常，但固定测试作品首集未起播。经当前系统代理对照，第 1、78、155 集各请求三次，旧接口仍全部返回 `API_EMPTY`。因此没有把延迟重试当成此次修复。

参考项目于 2026-10-21 发布的 [1.0.18](https://github.com/waligoraamodio288-rgb/hongguo-desktop-releases/releases/tag/v1.0.18) 提供了公开播放器适配组件。下载其第三方对应源码归档，核对 SHA256 为 `403335f0bf5299b4bc654d084f2537f06a10e863affa8b0c9b63ef134fdd8aee`，静态阅读 `desktop-catalog-1.0.18/desktop_public_player.py`，未运行参考安装程序，也未将该 Python 文件打入本项目。

其协议改为 `api5-normal-sinfonlineb.fqnovel.com` 的 `/novel/player/multi_video_model/v1/`，按编号从批量结果中提取当前分集，使用公开访客参数及 `video_platform=1024`。保留本机已有播放器标识进行独立对照，第 1、78、155 集均取得 `code=0` 和对应资源模型；结果不是仅凭发布说明推断。

## 最小修复

在 TypeScript 传输层独立实现上述请求协议，每次批量中只请求当前一个编号，严格选择该编号对应的模型；错误编号、缺失模型和业务失败均明确报错。其他内容接口继续原有签名路径，原播放器标识文件保留，不在失败后轮换。

真实处理发现新模型将轨道参数移入 `video_meta`、加密参数移入 `encrypt_info`。补充映射到既有资源校验后，继续按可解码编码筛选及原画质优先级选轨；缺失加密标记或不支持加密方式仍拒绝。下载大小检查、完整媒体处理、滚动缓冲、收藏和进度流程保留。
